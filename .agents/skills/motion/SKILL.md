# Motion

Read only the child skill that answers the current task, then its relevant
references. Add another only for a distinct concern.

Use `microinteractions` for triggers and feedback, `animate` for web implementation, `animate-expo` only for Expo, `improve-animations` for an audit, or the vocabulary for naming an effect. `review-animations` retains its explicit-invocation scope. `apple-design` translates Apple ideas to the web; it is not native SwiftUI API guidance.

For WinUI, SwiftUI, Compose, or GTK implementation, use the platform group. Motion should explain state change, remain interruptible, and respect accessibility settings; do not add layout animation merely to create activity.
